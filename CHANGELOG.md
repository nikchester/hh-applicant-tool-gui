# Изменения

## 0.3.1 — 2026-11-10

Неподходящее письмо больше не останавливает автоотклики.

### Исправлено

- Если письмо не прошло проверку, программа пропускает только эту вакансию и продолжает запуск.
  Раньше одно письмо с «джун/миддл» для вакансии без Senior/Lead останавливало все автоотклики.
  По пропущенной вакансии отклик не уходит.
  Три отклонённых письма подряд останавливают запуск: так программа сигналит о проблеме в промпте или модели.
- Журнал GUI показывает причину отклонения, вакансию, работодателя и текст отклонённого письма.
- Проверка уровня ищет `junior` и `middle` только целым словом. Слова вроде `middleware`
  и `juniors` больше не отклоняют письмо. «Джуна» и «миддла» проверка по-прежнему находит.
- Если запуск остановила проверка программы, итоговое сообщение называет её причину.
  Раньше GUI советовал проверить вход в HH и AI-провайдера, хотя оба работали.

## 0.3.0 — 2026-11-09

Выбор AI-провайдера, поиск по резюме без запроса, автозагрузка резюме и повторы при сбоях связи.
Программа переименована из PocketNode в hh-applicant-tool-gui.

### Новое

- Поиск без запроса: режим «Все подходящие для резюме» берёт вакансии, которые HH подбирает
  под резюме (`/resumes/{id}/similar_vacancies`). Режим сохраняется отдельно для каждого резюме
  и работает в обходе всех резюме по кругу.
- Редактор «Стиль письма…» в шаге 3: инструкция, по которой ChatGPT пишет каждое письмо.
  Редактор проверяет подстановки и знак %, не сохраняет текст с ошибкой
  и умеет вернуть исходный стиль.
- AI-провайдеры (#3): кроме ChatGPT через ChatMock — OpenAI-совместимый API по ключу
  и локальная модель (Ollama, LM Studio). Ключ хранится в диспетчере учётных данных Windows.
  Сетевые фильтры пропускают только маршруты моделей выбранного провайдера;
  ChatMock запускается только для варианта ChatMock.
- Резюме загружаются сами при запуске и после входа в HH. Кнопка «Обновить список резюме»
  загружает их заново.
- Звук и мигание на панели задач, когда GUI нужен пользователь. Сигнал звучит при ошибке
  или предупреждении любого действия и в конце предпросмотра, откликов, автооткликов
  и ответов в чатах. Звук зависит от результата: ошибка, предупреждение или успех.
  Кнопка на панели задач мигает, пока окно не станет активным. Остановка кнопкой
  «Остановить» сигнала не даёт. Перед окном «Капча» GUI тоже даёт сигнал предупреждения
  и пишет в журнал, что HH ждёт ввода.
- Если HH отклоняет отклик кодом ошибки, в причине остановки теперь есть сводка ответа:
  тип содержимого, путь редиректа, `X-Request-Id`, размер тела, коды ошибок JSON
  и признаки капчи, `_xsrf`, входа или антибот-защиты. Для JSON сводка показывает
  имена ключей без значений. Тело ответа, cookies и токены в журнал не попадают.
- Повторы при сбоях связи в откликах и автооткликах. Если шлюз модели не смог
  соединиться с AI-провайдером, письмо генерируется повторно: до 3 попыток с паузой 30 с.
  После третьей неудачи вакансия пропускается без отклика. Если подряд пропущены
  2 вакансии, запуск останавливается. Если HH не ответил на отклик, через 15 с GUI
  проверяет вакансию в HH (`relations`). Отклик есть — он засчитан, повтора нет.
  Отклика нет — тот же отклик отправляется ещё один раз. Проверка не удалась или
  повтор тоже без ответа — запуск останавливается, как раньше. Отклики с тестом
  пока не повторяются.

### Переименование PocketNode → hh-applicant-tool-gui

- Внутреннее имя PocketNode заменено именем репозитория. Программа теперь
  `hh-applicant-tool-gui.exe`, установщик — `hh-applicant-tool-gui-<версия>-windows-x64-setup.exe`.
  Название в окне и ярлыках («Автоотклики HH») и `AppId` установщика не изменились:
  новый установщик обновляет старую установку и удаляет `PocketNodeHH.exe`.
- Папки профиля: `~/.config/pocketnode-hh` → `~/.config/hh-applicant-tool-cli`,
  `~/.config/pocketnode-hh-gui` → `~/.config/hh-applicant-tool-gui`, так же в `~/.local/state`.
  Ключ API: запись `PocketNodeHH/ai-provider/<хост>` → `hh-applicant-tool-gui/ai-provider/<хост>`.
- `profile_migration.py` один раз переносит старые папки при запуске GUI и скриптов PowerShell,
  GUI переносит и ключ API. Если новая папка уже есть, перенос её не трогает и старую не удаляет.
  Если папка занята старой версией, программа просит её закрыть и ничего не запускает.
- Переменные окружения `POCKETNODE_HH_*` → `HH_APPLICANT_TOOL_*`,
  mutex `Local\PocketNode-HH-Run` → `Local\hh-applicant-tool-gui-run`.

### Исправлено

- Если сервер не ответил (тайм-аут или обрыв соединения), GUI пишет «Нет связи с сервером …»
  и советует проверить интернет или VPN. Раньше GUI показывал подсказку действия:
  например, при входе в ChatGPT просил ввести код, хотя код ещё не пришёл.
  Фоновый процесс передаёт в GUI только имя сервера, без адреса запроса.
- Ответы в чатах больше не останавливаются, когда узел `chatik.hh.ru` срывает подключение.
  Если узел не ответил за 4 секунды, программа подключается к узлу `api.hh.ru`:
  он обслуживает и `chatik.hh.ru`. До конца запуска запросы идут через этот узел.
  Имя в TLS и проверка сертификата остаются для `chatik.hh.ru`, поэтому чужой узел
  программа отклоняет. Повтор идёт до отправки запроса, поэтому ответ не уйдёт дважды.
  Журнал GUI пишет, когда программа переключилась на резервный узел.
- GUI показывает ожидание следующего вопроса робота-рекрутера в том же чате.
  Раньше это сообщение видел только PowerShell, а GUI молчал до 60 секунд.
  Теперь журнал пишет начало и итог ожидания, а строка состояния показывает обратный отсчёт.
  Итог ожидания: новый вопрос, робот вышел из чата, время истекло или чат пропущен.
- Вакансии с тестом больше не пропускаются с ошибкой `missing 1 required positional argument`.
- Письмо может назвать уровень из названия вакансии («Junior …»): проверка уровня
  больше не останавливает из-за этого автоотклики.
- Журнал показывает причину остановки, если её назвала проверка приложения.
- Капча на отклике с тестом больше не останавливает запуск. HH отвечает на форму теста
  `403` с `hhcaptcha.captchaState`. Программа показывает окно «Капча» и после ввода
  один раз повторяет ту же форму с полями `captchaText`, `captchaKey` и `captchaState`.
  Повторная капча, отмена или пустой ввод останавливают запуск без новых попыток.
- Счётчики GUI учитывают отклики с тестом и капчу на них.
- Журнал и другие поля только для чтения копируются: `Ctrl+C` работает и в русской раскладке,
  `Ctrl+A` выделяет всё, правая кнопка мыши открывает меню «Копировать / Выделить всё».
  `Ctrl+C` без выделения копирует всё поле.

## 0.2.0 — 2026-11-05

Оконное приложение получило новое название, пошаговый сценарий и тёмную тему Windows 11.

### Новое

- Название в окне, ярлыках и установщике: «Автоотклики HH» вместо «PocketNode HH».
- Экран «С чего начать»: что делает приложение, что для него нужно и порядок работы.
  Синяя кнопка всегда запускает следующий шаг.
- Шаги с состоянием: ✓ готово, ▶ текущий, ○ недоступен. Недоступный шаг называет причину.
  Полоса «Настройка: N из 3 шагов» показывает прогресс.
- Окно помнит выполненный вход в HH и ChatGPT.
- Вход в HH: поле ввода стоит под кнопкой входа, подпись совпадает с запросом, ввод не скрывается.
- Вход в ChatGPT: отдельное окно с кодом и кнопками «Открыть страницу входа» и «Скопировать код».
- Строка статуса по образцу Fluent InfoBar: цвет и значок показывают важность сообщения.
- Тёмная тема Windows 11 и тёмный заголовок окна.
- Переключатель «Вакансия или вопрос» / «Журнал»: выбранный пункт выделен яркостью и полосой.
- Счётчики вакансий и отправок во время работы.

### Изменено

- Поисковый запрос и модель сохраняются сами; кнопка «Сохранить настройки» удалена.
- Автоотклики свёрнуты в блок «Дополнительно». Поля проверяются сразу, кнопка запуска
  заблокирована до исправления ошибки.
- Одна кнопка «Остановить»; «Прервать сразу…» появляется только после запроса остановки.
- Тексты сообщений переписаны простым языком; ошибка называет действие и следующий шаг.
- Номер версии задаётся в одном месте: `APP_VERSION` в `windows/packaging/manifest.py`.

### Исправлено

- Ручной ввод капчи всегда завершался ошибкой. `hh-applicant-tool` 2.3.7 вызывает
  `session.get(url, params)` позиционно, а `requests` такой вызов отклоняет.
  `manual_captcha.py` адаптирует только сессию капчи и только на время решения.
- CI не останавливался на упавших тестах: PowerShell проверял код выхода только последней команды шага.
  Теперь шаг падает, если упал любой набор тестов.

### Совместимость

- Папки профиля, имя `PocketNodeHH.exe`, mutex и `AppId` установщика не изменились.
  Входы и настройки сохраняются, установщик обновляет версию 0.1.0 на месте
  и удаляет ярлыки со старым названием.

### Известные ограничения

- Сборка не подписана: SmartScreen может показать предупреждение.
- Реальные входы и отклики проверяются только вручную: автотесты работают без аккаунтов и сети.
- Право на перераспространение `hh-applicant-tool` не подтверждено: в его wheel лицензия не указана.
